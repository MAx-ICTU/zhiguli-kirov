# Backend и админка

Публичный каталог остается статическим и продолжает работать на GitHub Pages. Backend запускается отдельно для рабочего кабинета магазина: редактирование товаров, прием заявок и будущая синхронизация с учетной системой.

## Запуск

```bash
npm run admin
```

Админка и API будут доступны по адресу:

```text
http://localhost:4173/admin.html
```

Для закрытого режима задайте токен:

```bash
ADMIN_TOKEN=admin-secret MANAGER_TOKEN=manager-secret npm run admin
```

После этого запросы к рабочему кабинету должны передавать заголовок:

```text
Authorization: Bearer manager-secret
```

Если админка открыта в браузере, она покажет форму входа и сохранит рабочий токен в этом браузере. Токен `MANAGER_TOKEN` открывает товары и заявки. Токен `ADMIN_TOKEN` дополнительно разрешает проверку, публикацию и откат прайса, а также изменение настроек. В верхней панели есть кнопка выхода, чтобы сменить роль без очистки данных браузера.

## Что уже есть

- `GET /api/health` - проверка работы backend.
- `GET /api/catalog/summary` - сводка по каталогу и разделам.
- `GET /api/products` - список товаров с поиском, разделом, статусом и пагинацией.
- `GET /api/products/:code` - карточка товара.
- `PATCH /api/products/:code` - сохранение ручных правок товара, роль `manager` или `admin`.
- `POST /api/requests` - прием запроса покупателя.
- `GET /api/requests` - список входящих запросов для менеджера, роль `manager` или `admin`.
- `PATCH /api/requests/:id` - смена статуса входящего запроса, роль `manager` или `admin`.
- `POST /api/imports/preview` - предварительная проверка нового прайса, роль `admin`.
- `POST /api/imports/:id/apply` - публикация проверенного импорта, роль `admin`.
- `POST /api/imports/:id/rollback` - откат каталога к состоянию до публикации, роль `admin`.
- `GET /api/imports/history` - история публикаций каталога, роль `admin`.
- `GET /api/session` - текущая роль и права по переданному токену.
- `GET /api/settings` - рабочие настройки каталога, роль `manager` или `admin`.
- `PATCH /api/settings` - изменение рабочих настроек каталога, роль `admin`.
- `GET /api/sync/status` - статус готовности к будущей синхронизации.

## Роли

В закрытом режиме поддерживаются две роли. `manager` работает с заявками покупателей и карточками товаров. `admin` имеет те же возможности и дополнительно управляет публикацией прайса, откатом публикаций и настройками.

Если токены не заданы, backend запускается в режиме разработки с правами `admin`.

## Заявки

В админке есть доска заявок с тремя состояниями: новые, в работе и закрытые. Менеджер видит телефон, комментарий покупателя и товары из списка запроса, после чего может перевести обращение в работу или закрыть его.

Уведомления на внешние контакты пока не включены. Новые обращения сохраняются только во внутреннем хранилище backend и видны в админке.

## Импорт прайса

Импорт работает в два шага: сначала админка показывает предварительную проверку, затем менеджер отдельно публикует каталог. Preview считает новые, измененные и исчезнувшие позиции, показывает примеры строк и запускает проверку качества прайса.

Публикация блокируется, если файл похож на неполную или поврежденную выгрузку: слишком мало товаров, каталог резко уменьшился, исчезла большая доля текущих позиций или много строк пропущено из-за пустых кодов, названий и дублей. Предупреждения не запрещают публикацию, но подсвечивают риск для ручной проверки.

Перед каждой публикацией backend сохраняет резервную копию текущего `src/products.js`. История импортов в админке показывает последние публикации и позволяет откатить каталог к состоянию до выбранного импорта.

Сейчас интерфейс принимает `.xlsx`, JSON, CSV, TSV и HTML-таблицы, которые иногда сохраняются с расширением `.xls`. Старый бинарный `.xls` определяется отдельно и получает понятное сообщение: такой файл нужно сохранить как `.xlsx` перед загрузкой.

## Хранение данных

Исходный каталог остается в `src/products.js`, чтобы не ломать опубликованный сайт. Ручные правки админки сохраняются в `server/data/catalog-overrides.json`, запросы покупателей - в `server/data/requests.json`, история публикаций - в `server/data/import-history.json`, настройки рабочего кабинета - в `server/data/settings.json`.

Такой слой можно заменить на SQLite/PostgreSQL без изменения публичного сценария: коды товаров из прайса сохраняются как стабильные внешние идентификаторы для будущей синхронизации.
